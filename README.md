# Thesis
Undergraduate thesis work. Generating a stereo event camera dataset for underwater applications.

Using 2 x Metavision Prophesee EVK4HD cameras in stereo configuration with a hardware synchronisation cable.

Data recording was done using the BlueROV2 as the vehicle. The computer used to record the data was an NVIDIA Jetson Orin.

## Useful commands

| Command      | Description |
| ----------- | ----------- |
| `metavision_viewer` | Prophesee metavision [viewer](https://docs.prophesee.ai/stable/samples/modules/stream/viewer.html#chapter-samples-stream-viewer). Allows for streaming and recording of camera data. |
| `metavision_platform_info` | Check all connected event cameras. |

## The utils folder

| Script     | High level usage |
| ----------- | ----------- |
| `bias_tuner.py` | Helps interactively tune biases for the event cameras.|
| `checkerboard_detection.py` | Runs checkerboard detection on a folder of greyscale images generated by E2VID. It also outputs a folder of matches with detected corners overlayed and, a csv file of all files and their matching status. |
| `raw_to_e2vid.py` | Converts `.raw` event camera data into the `.txt` format required as input by E2VID.|

### Recording

The following are some example commands to start the launch files with the appropriate parameters on my pc. The following launch files have more parameters that can be set but this is a somewhat minimal version of each.

#### Launch single camera

This is intended to be used to launch a single camera for calibration purposes.

```
ros2 launch evk4hd_camera_bringup evk4hd_record.launch.py \
    bag_prefix:=/home/ryan/unsw/thesis/ros_recordings/ \
    bias_file:=/home/ryan/unsw/thesis/camera_files/<bias_file>
```

#### Launch synched cameras

This is then used to record the synced stereo event camera data.

```
ros2 launch evk4hd_camera_bringup evk4hd_sync_record.launch.py \
    primary_serial:=00052135 \
    secondary_serial:=00052136 \
    bag_prefix:=/home/ryan/unsw/thesis/ros_recordings/sync \
    bias_file:=/home/ryan/unsw/thesis/camera_files/<bias_file>
```

These launch files only prepare the cameras, they do not immediately record. To start / stop the recording use the following.

```
# start recording
ros2 service call /start_recording std_srvs/srv/Trigger

# stop recording
ros2 service call /stop_recording std_srvs/srv/Trigger
```

### Conversion

These files will get recorded in a ROS bag and end up with a .db3 file format. Thankfully the [event camera tools](https://github.com/ros-event-camera/event_camera_tools) package provides some software to convert between the formats. Again for personal use here is a demonstration to convert the data from a single recording.

```
# Single camera recording
ros2 run event_camera_tools bag_to_raw \
    -b /home/ryan/unsw/thesis/ros_recordings/<bag_name> \
    -o /home/ryan/unsw/thesis/recordings/<output_file_name> \
    -c evk4 \
    -t /event_camera/events
```

For a synchronised event camera recording there will be two topics in the same bag which both have individual camera recordings. 

```
# For the primary camera
ros2 run event_camera_tools bag_to_raw \
  -b /home/ryan/unsw/thesis/ros_recordings/<sync_bag> \
  -o /home/ryan/unsw/thesis/ros_recordings/<primary_output> \
  -c evk4 \
  -t /event_camera_primary/events

# For the secondary camera
ros2 run event_camera_tools bag_to_raw \
  -b /home/ryan/unsw/thesis/ros_recordings/<sync_bag> \
  -o /home/ryan/unsw/thesis/ros_recordings/<secondary_output> \
  -c evk4 \
  -t /event_camera_secondary/events
```

There are more steps to then convert the raw files for calibration.

## Calibration (Once in db3 format, off the ROV)

For this project I settled on using [E2CALIB](https://github.com/uzh-rpg/e2calib) to convert the event streams into grayscale images which could then be used to perform standard camera calibration using OpenCV.

#### Conversion to h5 file format

Thankfully the repo for E2CALIB includes a conversion file which converts a range of formats into .h5 which E2CALIB can then read. Make sure you are **not** using the virtual environment for E2CALIB/E2VID first.

```
python3 convert.py <raw>
```

#### E2CALIB Reconstruction

On the page for the repo there is a description of all of the options for running the script. The command below is what has been used for this project.

First it is important to activate the environment required to run the script using conda / venv. The following is then a command to reconstruct images from the .h5 file.

```
python offline_reconstruction.py \
  --freq_hz 10 \
  --upsample_rate 2 \
  --h5file <data.h5> \
  --output_folder <output_folder> \
  --dataset_name <data_folder> \
  --height 720 \
  --width 1280 \
  --use_gpu
```

Only use the ```--use_gpu``` option if you have a gpu.

## E2VID 

Currently I am using the [E2VID](https://github.com/uzh-rpg/rpg_e2vid) to convert the event stream into greyscale images to perform checkerboard calibration. This is an older repository and I have made a fork to get it to run with a newer version of python / numpy. The fork can be found at E2VID [fork](https://github.com/ryan103a/e2vid). This version has branches for versions of the software to work on cpu and gpu, as well as with different pretrained models such as [FireNet](https://github.com/tylerchen007/firenet-pdavis).

Current setup:

- Raw event recordings stored in `recordings/` are transformed into `.txt` format using the *raw_to_e2vid.py* file in `utils/`. This is the format which E2VID requires as input.
- The `.txt` files are then processed using E2VID and the reconstructed greyscale image output is stored in `reconstructions/`.

This process is currently bottlenecked by the generation and processing of the `.txt` files. An alternative is being explored.

### Biases

Adjusting biases [link](https://docs.prophesee.ai/stable/hw/manuals/biases.html#chapter-biases). Includes information about the bais settings and what they do, as well as the limits for the EVK4-HD model. An example file for biases is `checkerboard_detection.bias`:

```
0 % bias_diff
60 % bias_diff_off
30 % bias_diff_on
10 % bias_fo
60 % bias_hpf
0 % bias_refr
```

Other bias files and settings json files can be found in the `camera_files/`. There is also a small bias tuning script *bias_tuner.py* in `utils/`.

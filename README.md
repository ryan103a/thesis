## The utils folder

| Script     | High level usage |
| ----------- | ----------- |
| `bias_tuner.py` | Helps interactively tune biases for the event cameras.|
| `checkerboard_detection.py` | Runs checkerboard detection on a folder of greyscale images generated by E2VID. It also outputs a folder of matches with detected corners overlayed and, a csv file of all files and their matching status. |
| `raw_to_e2vid.py` | Converts `.raw` event camera data into the `.txt` format required as input by E2VID.|

## Event camera stream with ROS2

Open source [metavision driver](https://github.com/ros-event-camera/metavision_driver). Currently installed on personal computer at `metavisoin_driver_ws`, more in depth information on their github page. This is more of a quickstart for me. Make sure to source ROS2 and the driver folder itself with: 

```
cd metavision_driver_ws
source install/setup.bash
```

The driver can then be run with:
```
ros2 launch metavision_driver driver_node.launch.py
```

The renderer can then be run with:
```
ros2 launch event_camera_renderer renderer.launch.py
```

Which can be viewed in RQT.

## E2VID 

Currently I am using the [E2VID](https://github.com/uzh-rpg/rpg_e2vid) to convert the event stream into greyscale images to perform checkerboard calibration. This is an older repository and I have made a fork to get it to run with a newer version of python / numpy. The fork can be found at E2VID [fork](https://github.com/ryan103a/e2vid). This version has branches for versions of the software to work on cpu and gpu, as well as with different pretrained models such as [FireNet](https://github.com/tylerchen007/firenet-pdavis).

Current setup:

- Raw event recordings stored in `recordings/` are transformed into `.txt` format using the *raw_to_e2vid.py* file in `utils/`. This is the format which E2VID requires as input.
- The `.txt` files are then processed using E2VID and the reconstructed greyscale image output is stored in `reconstructions/`.

This process is currently bottlenecked by the generation and processing of the `.txt` files. An alternative is being explored.

## Event camera calibration files

### Biases

Adjusting biases [link](https://docs.prophesee.ai/stable/hw/manuals/biases.html#chapter-biases). Includes information about the bais settings and what they do, as well as the limits for the EVK4-HD model. An example file for biases is `checkerboard_detection.bias`:

```
0 % bias_diff
60 % bias_diff_off
30 % bias_diff_on
10 % bias_fo
60 % bias_hpf
0 % bias_refr
```

Other bias files and settings json files can be found in the `camera_files/`. There is also a small bias tuning script *bias_tuner.py* in `utils/`.
